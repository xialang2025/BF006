# BF006 4G 软件候选与首板验收

## 4G-03 首板 IAP 与时序

首板为单相 220V 一控一旧板，之前未运行过新协议。该板无法通过 COM 口在线调试。首板验收使用独立回路，待现场记录板号、旧固件版本、旧参数版本、备份及烧录选项。允许擦除 EEPROM 是已知条件，实际擦除及读回结果待记录。

| 项目 | 已核对 | 首板待填写 |
| --- | --- | --- |
| 旧参数 | `Par_Init()` 从 `0x0000` 读取，`save_pro()` 原流程先擦后写。 | 参数镜像、版本、备份文件及恢复结果，烧录前后 EEPROM 读回对比。 |
| 可用区域 | 协议需要两个配置槽、两个身份日志扇区，迁移时另保留旧参数区。按 512 字节估算，迁移期需要 2560 字节。 | 实际擦除粒度、各区域起止地址、相邻区域独立擦除结果、已占用区。 |
| 最坏耗时 | `EEPROM_Trig()` 保存并清除 `EA`，触发完成后恢复。主循环通过保存函数发起擦写。 | 单次擦除、单字节写入、读回和完整保存的最大耗时，以及测试电压、温度、样本次数。 |
| 真实时基 | 定时器零当前为 1 ms 中断。定时器一供遥控，定时器二供 RS485，定时器四供 USART4。 | 独立时间参考与定时器零服务次数对比，验证 IAP 期间有无丢拍和可用的补偿方案。 |
| 保护及通信 | 软件回归覆盖 USART4 的 55 字节接收、56 字节丢弃、截断帧和静默后恢复。 | 实测 IAP 与 9600、8N1 长帧重叠时的丢字节行为，以及保护输入变化到继电器关断的最大延迟。 |

### 首板记录方法

1. 记录烧录配置和旧参数来源，先在独立板上备份旧参数。用读回对比证明烧录选项对旧区的影响。
2. 在选定的测试区域写入可辨识数据，逐个验证擦除粒度及相邻区域。填入实际可分配地址并标明旧区、配置槽、身份区。未知地址保持空白。
3. 用逻辑分析仪或示波器同时记录 IAP 窗口、定时器零服务和保护输出。已有 P5.5 同时用于 ADC 和定时器零，测量时应使用独立标记或区分来源。用独立时间参考比较跨 IAP 前后的实际经过时间。
4. 通过模块串口链路注入跨越擦写窗口的 9600 帧，核对截断帧无应答或被拒绝，并在静默后重发合法只读帧验证恢复。测试同时记录保护输出。

如果 IAP 期间不能恢复真实经过时间，带上下文的操作保持关闭，保留原 V1 只读快照。软件故障注入可验证提交和恢复规则，物理地址、实际擦写时延、保护延迟和定时器行为由上述记录确认。

## 4G-04 统一配置保存软件候选

双槽按协议使用 117 字节负载、页代次、CRC 和最后写入的提交标记。模拟验证了标记写入前的断电恢复、标记写入后第一次读回异常、旧区保留、面板量程及供排水整组提交、过时面板值拒绝和无可信配置时的启动门禁。默认固件未指定 `BF006_CONFIG_SLOT_A`、`BF006_CONFIG_SLOT_B`，继续使用既有保存流程。模拟构建使用的槽地址是仿真数据。

尚需完成以下工作：

- 用首板读回样本确认版本 17 和 18 的字段布局和旧区内容。确认真实擦除粒度后核对候选地址约束，并在独立回路做逐阶段断电。
- RS485 参数、设备地址和模式写入，以及面板参数和模式，已接入双槽提交。RF 解码在中断中交付，主循环处理学习和停泵。旧 RF 停泵立即断继电器、切手动，再保存。设备规格复位、自动整定和运行内部写者仍沿用即时更新与随后保存，CFG_REV 对这些入口的比较仍以 CRC 为依据。
- 将重新扫描、恢复发布和写后失败反馈纳入经过实测的保护延迟预算。候选的正常保存每次循环推进一步，重新扫描仍同步读回。RF 在中断中改配置时的原子性和优先停泵需单独验证。

新增首板步骤。确认槽位置后，用现场 RS485 连续写入两个不同量程，在第一个写入尚未落盘时发送第二个。预期第一个请求受理，第二个返回忙，读取在提交前显示原值，提交后显示第一个值。再断电上电，应恢复第一个值。测试保存期间遥控停泵，预期立即关断继电器并切手动，尚未落标的普通设置不会生效。

复现命令使用项目已有的 Keil C51 和 µCsim。`s51.exe` 参数填本机路径。

```powershell
python -X utf8 BF006_STC/pro/tests/run_4g_tests.py config_store_test Model_1PH_220_1C1_LCD s51.exe
```

## 4G-05 执行代次软件候选

双区身份日志实现显式代次写入、重启递增、分区换页和读回确认。仿真覆盖空白区拒绝自动启用、维护写入、跨区递增、部分写入、已提交记录损坏、代次耗尽及 OP=02H 的 127 字节和 OP=03H 的 78 字节应答。默认固件的 OP=02H、03H 返回 `32H`，OP=01H 仍提供原快照。

现场登记需绑定板号和云端设备身份，记录曾发放的最大代次。首次启用与身份丢失维修走不同登记记录。维修需要从记录确认未使用的新代次，保留旧日志镜像并在隔离回路验证后再恢复设备路由。普通 4G 不提供首配、擦除或回退指令。

板上步骤。先以已确认的 `BF006_CONFIG_SLOT_A/B`、`BF006_BOOT_SLOT_A/B` 构建隔离测试版。确认 Timer0 在最坏 IAP 窗口连续计时后才定义 `BF006_TIMER0_VERIFIED`。通过本地维护写入登记种子后冷启动，预期 OP=02H 和 03H 的代次为种子加一，每次重启递增，配置版本从一开始。再在空白或损坏身份日志上冷启动，预期两种上下文读取返回 `32H`，原 V1 快照继续可读。维护烧录入口及其设备登记核验仍需现场落实。

## 4G-06 单项读取软件候选

仿真遍历字段 1～28，对照原快照核对 50 字节短应答、127 字节完整应答、原字段宽度、实际零和填充值。另用模拟 IAP 驱动正式身份日志与计时入口，通过串口四核对同一条 OP=04H 应答的启动代次、计时和已保存配置。默认固件对合法 OP=04H 返回 `32H`。首板取得可信上下文后，逐项对照 OP=02H 和 04H，单相 B/C 应返回 `29H`，支持但未采样应返回 `35H`，真实零应置有效位。

## 4G-07 控制和历史结果软件候选

配置地址和时基已核验的构建可执行明确开泵、停泵、清故障和模式切换。结果使用普通和停泵两个槽，保存原请求和当时快照。模拟 IAP 已验证自动模式受理后仍显示手动，落盘后按原号查询确认，重启后恢复自动。循环模式要求给出已验证的 `BF006_CYCLE_LIMIT`，未核验或分钟数超限时拒绝。

板上步骤。依次切手动、自动和循环，在保存中及保存后按原号查询。预期只有落盘并发布后返回阶段 `03H`，同值返回 `04H` 且循环计时不清零。断电重启应恢复已确认模式。开停泵须核对实际继电器和运行状态。故障仍在时清故障应报 `22H`。独立后台收束和正式低内存布局仍需复核。

## 4G-08 单参数校验软件候选

OP=11H 接入配置事务和原号结果。模拟 IAP 验证量程写入受理、提交前保留旧值、保存确认和重启恢复。已覆盖超宽请求拒绝和合规同值免写。循环分钟受已核验的上限限制。

板上步骤。在手动停泵时按十项各发送一个合法目标，记录原编号。预期提交中只报告接受，提交后按原号返回确认及实际值。断电重启再读应得到已确认值。重复投递原请求应返回历史结果，改变同号请求任一字节应返回 `2BH`，不再次擦写。运行中或配置版本过旧时，应明确拒绝并保持参数。

## 4G-09 供排水组校验软件候选

组 01H 已接通统一保存。仿真验证方向和两个阈值在写入前都保持旧值，确认后按原号读取结果，断电模拟后恢复完整新组，量程保持。板上在手动停泵时发送合法三项组，分别在擦除、候选写入、提交标记前后断电。预期恢复完整旧组或完整新组，溢出阈值及其他参数保持。错误顺序、错误关系、开关量下改变阈值应整组拒绝。

## 4G-10 水泵保护默认组校验软件候选

组 02H 的四项保护值已接入统一保存和原号查询。单相 220V 和三相 380V 分别按本机构建核对欠压、过压、过载 10.0 A 和空载 0。板上先保存一组非默认保护值及可辨识的传感器参数，再发送本机四项默认值。预期提交后按原号确认，重启恢复四项默认值，其余参数保持。另一电压规格的目标值应返回 `2FH`。

## 4G-11 编辑竞争软件候选

普通控制在实际参数编辑和停泵进行中返回忙，停泵保留独立结果槽。验证编辑期间被拒绝的编号在退出编辑后仍不可执行。保存落标前复核时效、身份、配置版本及手动停泵资格。模拟已受理模式切换在落标前过期，重启保持手动，原号返回失败。符合资格的 4G 停泵可取消尚未落标的远程设置。

板上步骤。在进行保存时交错输入面板确认、RS485 写入、RF 停泵及 4G 停泵。预期只受理一个普通设置，符合资格的停泵优先。未落标请求应取消，已落标请求的结果按读回证据确认。实测各入口的时序和继电器响应。仍需核对即时运行写者与这套提交的全交叠。

## 4G-12 回绕与终态软件候选

可控时钟验证 5000 ms 后启停终态冻结、晚到状态不会改写原结果、同代次时间回退触发 `32H` 和新代次拒绝旧请求。仿真在回绕前预留 5000 ms 普通控制窗口。仍需把真实时基、持久代次推进、后台收束及保存证据重新扫描接成同一闭环，实体测试应跨 IAP 窗口验证。
