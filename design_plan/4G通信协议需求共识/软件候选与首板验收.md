# BF006 4G 软件候选与首板验收

## 4G-03 首板 IAP 与时序

首板为单相 220V 一控一旧板，之前未运行过新协议。该板无法通过 COM 口在线调试。首板验收使用独立回路，待现场记录板号、旧固件版本、旧参数版本、备份及烧录选项。允许擦除 EEPROM 是已知条件，实际擦除及读回结果待记录。

| 项目 | 已核对 | 首板待填写 |
| --- | --- | --- |
| 旧参数 | `Par_Init()` 从 `0x0000` 读取，`save_pro()` 原流程先擦后写。 | 参数镜像、版本、备份文件及恢复结果，烧录前后 EEPROM 读回对比。 |
| 可用区域 | 协议需要两个配置槽、两个身份日志扇区，迁移时另保留旧参数区。按 512 字节估算，迁移期需要 2560 字节。 | 实际擦除粒度、各区域起止地址、相邻区域独立擦除结果、已占用区。 |
| 最坏耗时 | `EEPROM_Trig()` 保存并清除 `EA`，触发完成后恢复。主循环通过保存函数发起擦写。 | 单次擦除、单字节写入、读回和完整保存的最大耗时，以及测试电压、温度、样本次数。 |
| 真实时基 | 定时器零当前为 1 ms 中断。定时器一供遥控，定时器二供 RS485，定时器四供 USART4。 | 独立时间参考与定时器零服务次数对比，验证 IAP 期间有无丢拍和可用的补偿方案。 |
| 保护及通信 | 软件回归覆盖 USART4 的 55 字节接收、56 字节丢弃、截断帧和静默后恢复。 | 实测 IAP 与 9600、8N1 长帧重叠时的丢字节行为，以及保护输入变化到继电器关断的最大延迟。 |

### 首板记录方法

1. 记录烧录配置和旧参数来源，先在独立板上备份旧参数。用读回对比证明烧录选项对旧区的影响。
2. 在选定的测试区域写入可辨识数据，逐个验证擦除粒度及相邻区域。填入实际可分配地址并标明旧区、配置槽、身份区。未知地址保持空白。
3. 用逻辑分析仪或示波器同时记录 IAP 窗口、定时器零服务和保护输出。已有 P5.5 同时用于 ADC 和定时器零，测量时应使用独立标记或区分来源。用独立时间参考比较跨 IAP 前后的实际经过时间。
4. 通过模块串口链路注入跨越擦写窗口的 9600 帧，核对截断帧无应答或被拒绝，并在静默后重发合法只读帧验证恢复。测试同时记录保护输出。

如果 IAP 期间不能恢复真实经过时间，带上下文的操作保持关闭，保留原 V1 只读快照。软件故障注入可验证提交和恢复规则，物理地址、实际擦写时延、保护延迟和定时器行为由上述记录确认。

## 4G-04 统一配置保存软件候选

双槽按协议使用 117 字节负载、页代次、CRC 和最后写入的提交标记。模拟验证了标记写入前的断电恢复、标记写入后第一次读回异常、旧区保留、面板量程及供排水整组提交、过时面板值拒绝和无可信配置时的启动门禁。默认固件未指定 `BF006_CONFIG_SLOT_A`、`BF006_CONFIG_SLOT_B`，继续使用既有保存流程。模拟构建使用的槽地址是仿真数据。

尚需完成以下工作：

- 用首板读回样本确认版本 17 和 18 的字段布局和旧区内容。确认真实擦除粒度后核对候选地址约束，并在独立回路做逐阶段断电。
- 将 RS485 参数及控制、RF 模式切换、设备规格复位、自动整定和其他直接写入纳入公共提交。候选当前跟踪现场配置变化并取消冲突中的面板提交，这些路径仍可能在持久化确认前改变运行值。现有配置比较以 CRC 检测变化，正式 CFG_REV 需要由各写入口精确推进。
- 将重新扫描、恢复发布和写后失败反馈纳入经过实测的保护延迟预算。候选的正常保存每次循环推进一步，重新扫描仍同步读回。RF 在中断中改配置时的原子性和优先停泵需单独验证。

复现命令使用项目已有的 Keil C51 和 µCsim。`s51.exe` 参数填本机路径。

```powershell
python -X utf8 BF006_STC/pro/tests/run_4g_tests.py config_store_test Model_1PH_220_1C1_LCD s51.exe
```
