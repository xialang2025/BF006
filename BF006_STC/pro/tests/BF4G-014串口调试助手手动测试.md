# BF4G-014 串口调试助手手动测试

适用于 BF006 测试板的 UART4 协议，线上 FMT 为 `03H`、设备信息修订为 `00H`。覆盖 `01H、02H、03H、04H、05H、06H、10H、11H` 八条指令。分别记录一控一、一控二的结果和实际相数。固件文件及 SHA-256 见[验收交接](BF4G-014验收交接.md)。

## 1. 接线和串口调试助手

1. 使用独立测试板，继电器输出不接实际水泵或动力负载。接线前确认板端调试口的电平和隔离条件。UART4 在 MCU 上使用 **P5.2（RXD4）** 和 **P5.3（TXD4）**。先按测试板图纸确定调试接头的信号定义，再将适配器 TX 接板端 RX，适配器 RX 接板端 TX。信号地按测试板的隔离接线方案连接，适配器 VCC 保持断开，由测试板原测试夹具供电。芯片复用脚见 [STC8H3K64S4 官方管脚说明](https://www.stcmicro.com/datasheet/STC8H3K64S4C_Features.pdf#page=6)。
2. 确保 UART4 只有调试助手这一条通信链路。断开原 4G 模块，关闭占用同一个 COM 口的脚本或软件。在设备管理器核对 USB 串口实际的 COM 号。
3. 打开 COM，设为 **9600 bps，8 数据位，无校验，1 停止位，无流控**。打开 **HEX 发送和 HEX 显示**，关闭自动加回车换行、自动加校验、定时发送和重复发送。每次只粘贴表格的一行完整请求，点击一次发送。
4. 收完一帧再发送下一帧，帧间至少留 **10 ms** 静默。手动操作可按 **1 秒**观察窗口判断是否出现应答。97 字节应答在 9600、8N1 下仅线上传输就约需 101 ms。调试助手分多行显示时，按字节连续拼接同一帧。
5. 保存带时间的 TX/RX 记录。普通用例按 **当前地址 01H** 编制。若板上设置了其他地址，先从面板或现场记录确认 P-11，再用第 9 节换址方法生成 R01。电脑拔插适配器、固件重启、地址发生变化后，先用只读查询确认通信。

**首次接通只发这一条**。地址 01H 的 R01 查询设备信息。

```text
01 43 BF 06 03 01 00 01 00 49 84
```

地址为 01H 时，正常收到 **27 字节**，前缀为 `01 43 BF 06 03 81 00 01 10 00 00`。若无应答，先检查 COM、TX/RX、电平、固件以及当前 P-11，确认发送的是 HEX 字节且未附加结束符。收到与发送完全相同的 11 字节时检查本地回显。收到乱码时先检查波特率、收发接线和板端信号。

## 2. 共用应答判读

| 整帧偏移 | 字节数 | 内容 |
| --- | --- | --- |
| 0 | 1 | ADR，设备地址 |
| 1～3 | 3 | 固定 `43 BF 06` |
| 4 | 1 | FMT，当前为 `03` |
| 5 | 1 | CMD，请求命令。应答为请求命令 OR `80H` |
| 6～7 | 2 | RID，正常请求为非零大端整数，应答原样回显 |
| 8 | 1 | LEN，DATA 字节数 |
| 9～8＋LEN | LEN | DATA。应答的第一个数据字节是 STATUS |
| 9＋LEN、10＋LEN | 2 | CRC 低字节、高字节 |

总长度为 `11 + LEN` 字节。DATA 的 u16、u32 值都是高字节先传，CRC-16/MODBUS 则低字节先传。完整应答做 CRC 运算的余数应为 0。任何 ADR、CMD、RID、长度、CRC 不符的帧都不能用作该条请求的验收证据。

成功时 STATUS 为 `00`。业务错误应答整帧为 **21 字节**，LEN 为 `0A`，DATA 格式如下。

```text
STATUS OBJ MIN[4字节大端] MAX[4字节大端]
```

表格错误预期中的前两字节依次为 STATUS、OBJ。范围未单列时，MIN、MAX 均为 0。区间读取的 OBJ 为起始号，单写为 P 参数号，控制为动作号。全局错误或无法确定对象时为 `FF`。

| 状态 | 判读 |
| --- | --- |
| 01H | 命令不支持 |
| 02H | FMT 不支持。可辨认的旧格式请求收到 FMT＝03H 的错误应答 |
| 03H | LEN、数量、区间或 RID 等结构错误 |
| 04H | 参数号、字段号、历史槽号或动作与目标组合无效 |
| 05H | 参数只读 |
| 06H | 本机型不适用 |
| 07H | 写值超范围或枚举无效，查看 MIN、MAX |
| 08H | 自动或循环模式拒绝普通启停 |
| 09H | 本地故障、锁定等保护阻止开泵 |
| 0EH | 配置尚未装载等短时不可受理状态，正常运行时可能无法遇到 |
| 无应答 | 先核对地址、CRC、截断和串口状态。写入或控制超时记为「结果未确认」，通过只读查询确认后再决定是否重试 |

## 3. 只读基线与六条读取指令

按 R01、R02、R03、R07～R10、R13～R16 做首次只读检查。把设备信息、两段全部参数、原模式和历史应答保存到同一份记录。试写前再单读目标参数并抄下 **Q 和原始整数值**。需要改址时记录原地址。需要做控制时，用 R10 的 Q＝00 数据确认原模式，另记录继电器停机状态。若 Q＝02 或 03，先等采样就绪或排查异常，结合面板核对，确认原模式后再做控制。

| --- | --- | --- | --- | --- |
| R01 | 设备信息 | `01 43 BF 06 03 01 00 01 00 49 84` | 成功，27 B | 核对相数、泵路数、额定电压与能力 001F |

### 3.1 01H 设备信息

下面是模拟机型的完整 R01 应答，适用于旧型号字为 A393H 的单相 220 V 一控二。现场按相数、泵路数、额定电压和能力位核对，CRC 以现场整帧为准。

```text
01 43 BF 06 03 81 00 01 10 00 00 A3 93 00 C9 01 02 00 DC 00 1F 61 10 09 08 0D 75
```

按 DATA 偏移从 0 开始判读。

| DATA 偏移 | 含义 | 示例 |
| --- | --- | --- |
| 0～1 | 状态、格式修订 | `00 00` |
| 2～3 | 旧型号字 | `A3 93` |
| 4～5 | 旧功能协议版本 | `00 C9`（201） |
| 6～7 | 相数、泵路数 | `01 02` |
| 8～9 | 额定电压 | `00 DC`（220 V）。380 V 为 `01 7C` |
| 10～11 | 能力位，bit0～4 分别为参数读取、运行读取、历史读取、单写、控制 | `00 1F` |
| 12～15 | 最大帧、参数、运行字段、历史区间上限 | `61 10 09 08`（97、16、9、8） |

### 3.2 02H 参数读取

成功 DATA 为 `00 起始P号 数量 [Q 值高 值低] × 数量`。R04 若原值为 100，应看到 DATA `00 03 01 00 00 64`，其中第 4 个字节为 Q，`0064H` 为十进制 100，即 10.0 A。R02、R03 连续覆盖 P-00～P-22。所有参数号在线上用一个 **十六进制字节**表示，例如 P-11 为 `0B`，P-17 为 `11`，P-22 为 `16`。

### 3.3 03H 运行字段

成功 DATA 为 `00 起始字段 数量 [Q 32位原值] × 数量`。R07～R09 覆盖 01H 到 18H 全部字段。

| 字段 | 含义与判读 |
| --- | --- |
| 01H | 工作电压，V |
| 02H／03H／04H | A 泵 A／B／C 相电流，原值÷10 为 A。单相的 B、C 相 Q＝01 |
| 05H／06H／07H | B 泵 A／B／C 相电流，同上。一控一全为 Q＝01，单相一控二的 B、C 相 Q＝01 |
| 08H | 运行状态。低四位 `1/6/A` 分别为手动／自动／循环。bit4、bit5 为 A、B 泵运行状态。bit6～8 为主备／轮换。bit9～11、12～14 分别是上、下池低中高位。bit15 及高 16 位为 0 |
| 09H | 优先故障代码，0 无故障，否则为故障位图最低置位的位号加 1 |
| 0AH | 活动故障位图 u32，见下文 |
| 0BH | 报警摘要。bit0 欠压、bit1 过压、bit2 过载、bit3 空载、bit5 缺相、bit6 上池高位、bit8 下池低位 |
| 0CH／0DH | 上／下池 LCD 六段位图，使用 bit0～5 |
| 0EH／0FH | 上／下池档位，0 低、1 中、2 高 |
| 10H | 连续工程值，原值÷100 为米或 MPa。浮球、电接点模式 Q＝01 |
| 11H | 状态标志，bit0 传感器错误、bit1 超过 P-20、bit2 系统溢流、bit3 上池闪烁或高位、bit4 下池闪烁 |
| 12H | 实际运行传感器类型，枚举同 P-18。切换未同步可见 Q＝02 |
| 13H | 当前作用水池，0 上池，1 下池 |
| 14H | 工程值单位，0 无连续单位、1 米、2 MPa |
| 15H | 连续量对应档位，0 低、1 中、2 高。浮球、电接点模式 Q＝01 |
| 16H／17H | 旧型号字、旧功能协议版本 |
| 18H | 功率占位，Q＝01、值为 0 |

故障位图的 bit0／1 为欠压／过压，bit2／3 为 A 泵过载／空载或干转，bit4～6 为 A 泵 A／B／C 相缺相，bit7／8 为 B 泵过载／空载或干转，bit9～11 为 B 泵 A／B／C 相缺相，bit12 为传感器异常，bit13／14 为 A／B 泵空载，bit15／16 为 A／B 泵锁定。高于 bit16 的位保留。用 R11 核对优先故障与位图，用 R10 在 Q＝00 时记录原模式和受控状态。

### 3.4 04H 故障记录

成功 DATA 为 `00 起始槽 数量 [Q 原故障号 电压u16 电流u16] × 数量`。电压以 V 计，电流原值÷10 为 A。R13 和 R14 覆盖槽 0～9。原故障号 0～16 与 0AH 的位号对应。

- `04 11 00 00 00 00` 表示空槽，`11H` 为十进制 17。
- `00 00 00 00 00 00` 表示欠压号 0 的有效条目，电压和电流都是零。
- Q＝02 时记录未就绪。故障号大于 17 时 Q＝03，保留原故障号、电压、电流。
- 用现有条目验收。若没有欠压样本，把该子项记为「未执行」。保存接线后和故障演练后的两段原报文。记录本身没有设备时间戳。

### 3.5 05H 与 06H 综合数据

一控一、一控二均可发这两条。DATA 偏移以 STATUS 为 0，以下偏移用十进制。机型特征 bit0＝三相、bit1＝一控二、bit2＝380 V，对应 220 V 单相一控一／一控二的值为 00H／02H，三相 380 V 对应 05H／07H。

| 项目 | 05H | 06H |
| --- | --- | --- |
| DATA 偏移 0、1 | 状态、机型特征 | 状态、机型特征 |
| 质量区 | 2～7，共 6 字节 | 2～10，共 9 字节，偏移 10 的 bit6～7 为 0 |
| 值区 | 8～52，共 45 字节 | 11～75，共 65 字节 |
| 保留区 | 53～62，10 字节全 00 | 76～85，10 字节全 00 |
| 整帧 | 74 字节 | 97 字节 |

每个质量字节从低位到高位存四项，每项占两位。第 `i` 项（从 0 数）取 DATA 中第 `2 + floor(i/4)` 字节，右移 `2 × (i mod 4)` 后与 `03H` 取交集。下表的偏移以各自**值区起点**计，读取时加上 05H 的 8 或 06H 的 11。

| 项索引 | 值区偏移／宽度 | 与 02H／03H 的数据来源 |
| --- | --- | --- |
| 0～3 | 0／2、2／2、4／2、6／2 | 03H 字段 01～04，电压与 A 泵各相 |
| 4～5 | 8／2、10／4 | 03H 字段 08、0A，运行状态与故障位图 |
| 6～9 | 14／1、15／1、16／1、17／1 | 03H 字段 0C～0F，上下池六段及档位 |
| 10～13 | 18／4、22／1、23／1、24／1 | 03H 字段 10～13，工程值、标志、类型、作用水池 |
| 14～17 | 25／2、27／2、29／2、31／2 | P-14、P-16、P-15、P-20 |
| 18～23 | 33／2、35／2、37／2、39／2、41／2、43／2 | P-00、P-01、P-03、P-02、P-06、P-07 |
| 24～26（06H） | 45／2、47／2、49／2 | 03H 字段 05～07，B 泵各相 |
| 27～30（06H） | 51／2、53／2、55／1、56／2 | P-04、P-05、P-12、P-17 |
| 31～34（06H） | 58／2、60／2、62／2、64／1 | 03H 字段 16、17、0B、15 |

选择稳定的两个对应字段核对原值和 Q，例如 P-03、P-14。以 P-03 为例，其项索引为 20，Q 在 DATA 偏移 7 的低两位，值在 05H 的 DATA 偏移 45～46 或 06H 的 DATA 偏移 48～49。原值为 100 时，两帧对应值均为 `00 64`。另核对 06H 的故障、运行状态和不适用相。实时电压与电流可能随两次请求的采样时间变化。应答CRC 前的 10 个保留字节应全为零。连续进行数次逐帧查询，记录是否都收足长度，以及是否混入可见的文本或额外字节。

## 4. 10H 单写参数

只在独立测试板上执行。先读原值，确认 Q＝00 并记录原始整数。建议完成一项试写和读回后立即恢复该项，再开始下一项。成功整帧 15 字节，应答 CMD＝90H、LEN＝04H，DATA 为 `00 参数号 RAM值u16`，随后以 02H 核对实值。RAM 写入和后台掉电保存分别记录。

| 用例 | 操作 | HEX 请求（整帧） | 预期 | 检查点 |
| --- | --- | --- | --- | --- |
| W01 | P-03 试写 120（12.0 A） | `01 43 BF 06 03 10 00 2F 03 03 00 78 AB B7` | 成功，15 B | DATA `00 03 00 78` |
| W02 | P-03 恢复 100（10.0 A） | `01 43 BF 06 03 10 00 30 03 03 00 64 3F BC` | 成功，15 B | 原值确为 100 才用。DATA `00 03 00 64` |
| W03 | P-03 写 901（90.1 A） | `01 43 BF 06 03 10 00 31 03 03 03 85 C2 C4` | `07 03`，MIN＝0，MAX＝900 | 越界。原值保持 |
| W04 | 尝试写只读 P-21 | `01 43 BF 06 03 10 00 32 03 15 00 01 67 93` | `05 15` | 拒绝写入 |

1. **正常写和同值写**。用 R04 记录原值，选与原值不同且在范围内的试值。P-03 原值不是 120 时可用 W01。原值恰为 120 时，可按第 9 节生成试写 100 的帧，并预先生成恢复 120 的帧。发试写帧后读 R04，再原样重发这条试写帧，确认相同 RID 能应答且数值不变。相同值不重复置保存标志，串口只可证实应答和读回。如需确认 IAP 次数，按第 8 节取仪器证据。
2. **非法写**。发送 W03 后再读 R04，值应与发送 W03 前一致。W04～W07、W15 也可核对拒绝前后的参数。W08～W11 专用于一控一，勿在一控二照抄这四条。
3. **量程边界**。用 R06 确认 P-14 原值为十进制 10 时，可在同一轮先试 W12 的超 1 拒绝，再试 W13 的等于上限。如果量程不同，按第 9 节生成 `P-15=当前 P-14` 和 `P-15=当前 P-14+1` 两条。恢复用 P-15 现场原值。调整多项时，先扩大后恢复较高阈值，先降阈值后缩量程，避免恢复值被范围检查拒绝。P-14 为 0 时只有零阈值合法。
4. **恢复读回**。仅当 P-03 原值是 100 使用 W02，仅当 P-15 原值是 9 使用 W14。其他原值按第 9 节生成。使用 R04、R06 或相应区间读回，核对 Q、原值、地址。试写或恢复超时后，先读回写入项。读回为原值时记录已核对，为试值时按原值恢复，为其他值或数据不可用时保留待恢复记录并先查原因。

开泵、停泵或切模式超时时，停止后续用例，优先确认测试板的实际输出。串口可用且板在手动模式时，发 C02 明确清除开泵意图，再用 R10 和现场观察核对。模式未确认时，已记录原模式的独立测试板可先发 C01 再发 C02。应答无法确认或输出仍异常时，按测试台本地停机流程处理。单次 R10 的运行位为零只能记录当时状态。

继电器观察与串口读回不一致时，分别登记应答、R10／R11 和现场观察。恢复原循环模式时会进入新的阶段。

## 6. P-11 改址与恢复

完成第 7 节错误帧验证和其他常规用例后，把改址作为最后一项写入演练。串口只连接本测试板。用 R05 确认原地址 01H，用 A01 确认试验地址 02H 当前静默。改址前备好从试验地址恢复原地址的请求。现场地址不同时，在第 9 节分别生成两个只读探测帧、正向改址帧和恢复帧。

## 8. 现场记录、扩展检查和收尾

## 9. 当前值和地址不同，如何重算 HEX

下面的 PowerShell 可在终端生成纯 HEX 字符串。复制输出到调试助手再发送。

- 新写或恢复参数时，用 `New-Bf4gRequest` 填当前地址、命令、RID 和 DATA。
- 把表中现成请求换到实际地址时，用 `Convert-Bf4gTestAddress` 并复制整行原请求。E15～E19 的异常格式、RID、LEN、CRC 和截断会按原用例保留。A02／A05 等改址写请求的 DATA 含目标地址，要用 `New-Bf4gRequest` 分别生成。
- 需要独立查 CRC 时，用 `Get-Bf4gCrc16`。校验完整应答的结果应为 0。

```powershell
function Get-Bf4gCrc16([byte[]]$Bytes) {
    $crc = 0xFFFF
    foreach ($value in $Bytes) {
        $crc = $crc -bxor $value
        for ($bit = 0; $bit -lt 8; $bit++) {
            if ($crc -band 1) {
                $crc = ($crc -shr 1) -bxor 0xA001
            } else {
                $crc = $crc -shr 1
            }
        }
    }
    $crc
}

function New-Bf4gRequest {
    param(
        [ValidateRange(1, 254)][int]$Address,
        [byte]$Command,
        [ValidateRange(1, 65535)][int]$Rid,
        [byte[]]$Data = @()
    )
    if ($Data.Count -gt 86) { throw 'DATA > 86 bytes' }
    [byte[]]$packet = @($Address, 0x43, 0xBF, 0x06, 0x03, $Command,
        ($Rid -shr 8), ($Rid -band 0xFF), $Data.Count) + $Data
    $crc = Get-Bf4gCrc16 $packet
    $packet += [byte[]]@(($crc -band 0xFF), ($crc -shr 8))
    ($packet | ForEach-Object { '{0:X2}' -f $_ }) -join ' '
}


function Convert-Bf4gTestAddress {
    param(
        [ValidateRange(1, 254)][int]$Address,
        [Parameter(Mandatory)][string]$Hex
    )
    [byte[]]$packet = $Hex.Trim() -split '\s+' |
        ForEach-Object { [Convert]::ToByte($_, 16) }
    if (($packet.Count -ne 8 -and $packet.Count -lt 11) -or
        $packet.Count -gt 97 -or
        $packet[1] -ne 0x43 -or $packet[2] -ne 0xBF -or $packet[3] -ne 0x06) {
        throw 'Expected a request from the BF4G-014 table'
    }

    if ($packet.Count -eq 8) {
        # 保留 E19 的截断长度。
        $packet[0] = $Address
    } else {
        $crcLow = $packet.Count - 2
        $crcHigh = $packet.Count - 1
        [byte[]]$prefix = $packet[0..($crcLow - 1)]
        $wireCrc = [int]$packet[$crcLow] -bor ([int]$packet[$crcHigh] -shl 8)
        # 用原 CRC 差值保留 E18 的故意错码。
        $delta = $wireCrc -bxor (Get-Bf4gCrc16 $prefix)
        $prefix[0] = $Address
        $crc = (Get-Bf4gCrc16 $prefix) -bxor $delta
        $packet[0] = $Address
        $packet[$crcLow] = $crc -band 0xFF
        $packet[$crcHigh] = $crc -shr 8
    }
    ($packet | ForEach-Object { '{0:X2}' -f $_ }) -join ' '
}

# 校验生成器。此命令应得到 R01，结尾为 49 84。
New-Bf4gRequest -Address 1 -Command 0x01 -Rid 1

# 仅示例。当前地址 02H，原 P-03 读回 135 时，生成恢复该值的帧。
$original = 135
New-Bf4gRequest -Address 2 -Command 0x10 -Rid 0x0100 `
    -Data @(0x03, ($original -shr 8), ($original -band 0xFF))

# 普通查询和故意坏 CRC 的用例都可换到地址 05H。
Convert-Bf4gTestAddress -Address 5 -Hex '01 43 BF 06 03 01 00 01 00 49 84'
Convert-Bf4gTestAddress -Address 5 -Hex '01 43 BF 06 03 01 00 60 00 61 14'

# 改址例。现场原地址为 05H，拟临时改到 06H。
$originalAddress = 5
$testAddress = 6
New-Bf4gRequest -Address $originalAddress -Command 0x01 -Rid 0x0101
New-Bf4gRequest -Address $testAddress -Command 0x01 -Rid 0x0102
# 确认原地址响应且试验地址静默后，才使用这一条试写。
New-Bf4gRequest -Address $originalAddress -Command 0x10 -Rid 0x0103 -Data @(0x0B, 0, $testAddress)
# 试写后，从试验地址读回 P-11。
New-Bf4gRequest -Address $testAddress -Command 0x02 -Rid 0x0104 -Data @(0x0B, 1)
# 恢复帧，在试验地址确认生效后使用。
New-Bf4gRequest -Address $testAddress -Command 0x10 -Rid 0x0105 -Data @(0x0B, 0, $originalAddress)

# 把收到的一整帧 HEX 放到数组中，校验成功返回 0。
$frame = [byte[]]('01 43 BF 06 03 01 00 01 00 49 84'.Split(' ') |
    ForEach-Object { [Convert]::ToByte($_, 16) })
```
